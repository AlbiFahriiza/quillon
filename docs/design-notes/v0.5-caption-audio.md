# Design note v0.5 — Caption & Audio Lanjut

Date: 2026-11-19 · Scope source: `myquillonplan.md` §12 v0.5, F5; research/H §1
(subtitle crates), research/M §1, §4 (loudness, caption burn-in edit-op).
Owner: build agent, per Panoptes protocol.

## 1. Task, scope, acceptance

Scope (plan §12 v0.5, verbatim): SRT/VTT/ASS import/export, whisper-rs
(optional), timing regularization, styled burn-in; `audio analyze`
(LUFS/true peak/silence per scene).

Acceptance criteria (each proven by a real command whose output is read):

1. SRT in → caption document out → burn-in rendered. Command path:
   `quillon caption import subs.srt --doc video.json -o out.json` then
   `quillon render out.json --format png --out frames/`; a frame inside a
   cue's range must differ (sha256) from a frame outside every cue, and the
   caption corpus document joins the golden hash corpus.
2. A whisper transcript passed through regularization yields caption
   durations within the min/max bounds (tested with a synthetic
   click-track). Commands: a `quillon-audio` test generates a click-track
   WAV, transcribes it (whisper when the `transcribe` feature and model are
   available; a deterministic onset detector otherwise), regularizes, and
   asserts every cue duration lies in [min, max] and covers its click.
   The real-whisper run is executed locally (model downloaded once) and its
   output kept as evidence; CI runs the deterministic path only.
3. SRT → document → SRT round-trip preserves timing. Command: `quillon
   caption import` then `quillon caption export`; the exported SRT must
   keep every cue's start/end millisecond values exactly (integer math:
   ms→tick and tick→ms are exact inverses at the flicks timebase).

Non-goals (this phase): MCP tool surface changes (plan §8 is the v0.4
contract; captions flow through existing validate/render tools); full ASS
styling round-trip (timing + text only, override tags stripped); OTIO;
`--smart-copy`; new easing/element types; transcribe as a mandatory
dependency (plan §15 #7).

## 2. Design decisions

D1 — Caption tracks live at document level, next to `audio`. A
`CaptionTrack { style: CaptionStyle, cues: Vec<CaptionCue> }` is added as
an optional `captions: Vec<CaptionTrack>` field on `Document`.
`CaptionCue { from: i64, to: i64, text: String }` uses document-timeline
ticks. Rationale: SRT/VTT cue timing is global to the video and routinely
crosses scene boundaries; making cues scene elements would force splitting
them at scene borders and would not round-trip. Burn-in draws on top of
the fully composited frame (after any crossfade), which matches how
subtitles are perceived and keeps the caption layer out of scene
compositing.

D2 — Schema stays `v: 1`; the field is optional and additive. Rationale:
documents without captions remain byte-identical; `deny_unknown_fields`
means older 0.x readers reject the new optional field, which is acceptable
pre-1.0 (crate semver carries compatibility; plan §14 reserves a `v` bump
for a mandatory migration, which an optional field is not). The schema
resource and `docs/schema.json` are regenerated in the same step that adds
the model.

D3 — SRT and VTT are parsed and serialized by our own code in
`quillon-core` (research/H §1: trivial, no dependency). Reading is
tolerant: UTF-8 BOM, CRLF or LF, `,` or `.` as the millisecond separator,
optional hours in VTT timings, ignored VTT cue settings and NOTE blocks,
blank final block tolerated. Writing is strict and canonical: LF endings,
SRT uses `,mmm`, VTT writes `WEBVTT` then hours-always timings. Timing
conversion is integer-exact at the flicks timebase (ms × timebase / 1000
and back), so the round-trip assertion is exact, not approximate.

D4 — ASS import goes through `rsubs-lib 0.4.0` (verified live on
crates.io today: MIT, 2026-10-07) as a `quillon-cli` dependency. We take
cue text and timing only; ASS override tags (`{\...}`) are stripped except
`\N` → newline, and styling is Quillon's default `CaptionStyle` (the same
defaults as SRT import; overridable with the same `--style` flags). ASS
style fields are deliberately not mapped. Rationale: research/H names
rsubs-lib as the maintained ASS parser; full ASS style mapping is a
non-goal, and importing the dependency into core would tax every core
consumer for a CLI-level format concern.

D5 — Timing regularization is ours and lives in `quillon-core` (research/H
§1: raw parser output is never burned directly). `RegularizeConfig { min_duration, max_duration, max_cps, merge_gap }` with defaults
`1.0 s / 6.0 s / 18 chars-per-second / 0.5 s` — these are our own product
defaults, chosen for comfortable reading; they are configurable per call
and are not claimed to be any broadcast standard. Pipeline order:
(a) split cues whose text is too long to fit `max_duration` at `max_cps`
(words split at boundaries, never mid-word), (b) merge adjacent cues whose
gap ≤ `merge_gap` when the merged cue still satisfies max duration and
cps, (c) clamp each duration into [min, max], extending `to` first, then
pulling `from` back, (d) enforce duration ≥ chars / max_cps (capped at
max), (e) resolve overlaps left-to-right (an earlier cue keeps its end).
Post-conditions asserted by property tests: cues sorted, non-overlapping,
every duration in [min, max] when the document length allows, and cps ≤
max. All math is in ticks (integers), deterministic.

D6 — Burn-in reuses the existing text rasterization path. For each track
whose cue covers the tick, the renderer synthesizes a `TextElement` (text,
font from the style's font asset, size, color, align, optional shadow),
rasterizes it with the same `text::rasterize` used by text elements, and
composites it — plus an optional background box layer — on top of the
final canvas. Position: `bottom | center | top` plus a margin (default
48 px), horizontally centered by default with the style's align applied.
Multi-line cue text uses embedded newlines. Determinism: fonts are
document-pinned assets, identical to text elements. Documents without
`captions` take a no-op path, so the existing golden corpus must not shift
(proven by the golden tests staying green with no refresh) and
`RENDERER_VERSION` stays 2.

D7 — Frame cache keys gain caption state, precisely. `frame_key` hashes,
for each track, the style, the font asset id + hash, and the cues active
at that frame's tick (not the whole track). Rationale: plan §F7's promise
is "edit scene 3 → only scene 3 re-renders"; hashing only active cues
extends the same promise to cue edits (editing cue 7 invalidates only
frames inside cue 7). A whole-track hash would over-invalidate.

D8 — `audio analyze` is a CLI subcommand over the existing mix pipeline.
`mix_document_decoding` produces the document mix, then per scene segment:
integrated LUFS (ebur128 `Mode::I`), true peak in dBTP (`Mode::TRUE_PEAK`,
max over channels), and silence ranges (sample magnitude below −50 dBFS
for ≥ 0.5 s — our defaults, configurable via flags). Output is human text
plus `--json` with per-scene and overall sections. ebur128's API
(`EbuR128::new`, `add_frames_f32`, `loudness_global`, `true_peak`) was
verified today from the vendored registry source, not from memory.

D9 — Whisper is a default-off feature `transcribe` on `quillon-audio`,
adding optional dependencies `whisper-rs 0.16.0` (Unlicense — NOTICE
entry) and `ureq` for the one-shot model download (both verified on the
registry the day they enter the manifest). The CLI gains `quillon caption
transcribe <audio>` behind `#[cfg(feature = "transcribe")]`: decode →
mono 16 kHz → whisper segments → cues → regularization (D5, always) →
inject into a document. The model is downloaded on first use to the
content-addressed cache with a pinned sha256 (default `ggml-tiny.en` from
the official whisper.cpp model repository). Rationale: plan §15 #7 keeps
transcription optional; feature-off builds must not gain a C toolchain
requirement. The whisper.cpp build needs cmake; the local environment
provides it via the pip cmake wheel, and CI gains a feature-check job.
Deviation risk (recorded): if the whisper.cpp build turns out unusable in
this environment, the feature ships compile-verified but runtime-untested,
and the acceptance report says exactly that — the deterministic click-track
path (acceptance 2) does not depend on it.

D10 — `disciplined.yaml` gains the missing `audio` layer. Finding: since
v0.3 the CLI imports `quillon-audio` (render `--lufs`), but
`disciplined.yaml` never declared `quillon-audio` as a layer, so
`arch_gate` could not see that edge. Fix: `audio: { paths:
[crates/quillon-audio], may: [core] }` and `cli.may += audio`, matching
plan §6.2 exactly. This tightens the gate (a previously invisible edge
becomes enforced); it does not loosen anything.

D11 — No MCP surface change. Plan §8 is the v0.4 tool contract; captions
reach agents through `validate_document` (schema/lint cover the new
field), `preview_frames`/`render_document` (burn-in renders), and
`diff_documents` (walks the JSON tree generically). A caption-specific
tool is deferred until an agent loop measurably needs it.

## 3. Layers and dependency direction

- `quillon-core`: caption model, validation, lint, builder, SRT/VTT
  parse/serialize, regularization. No new dependencies (arch layer rule:
  core depends on nothing internal; nothing external either).
- `quillon-render`: burn-in compositing. No new dependencies. May import
  `core` only (unchanged).
- `quillon-audio`: optional `transcribe` feature → `whisper-rs`, `ureq`.
  Default build unchanged. May import `core` only (unchanged).
- `quillon-cli`: `rsubs-lib` (ASS import) as a normal dependency; `audio
  analyze` uses `quillon-audio` (already a dependency). May import core,
  render, media, cache, audio (D10 makes the audio edge declared).
- Layering is enforced by `arch_gate` with the D10-corrected config; the
  one-way rule (plan §7 P7) is unchanged.

## 4. Steps, checkpoints, verification

Each step ends with the battery (`cargo fmt --check`, `cargo clippy
--workspace --all-targets -- -D warnings`, `cargo test --workspace`), a
commit, and a push; mid-build verification is the battery at every
checkpoint, read, not assumed.

1. Core model: `CaptionTrack`/`CaptionCue`/`CaptionStyle`, validation
   (non-empty text, `from < to`, sorted non-overlapping per track, font
   asset exists, cues within document duration), lint rule
   caption-vs-lower-third collision, builder method, schema regen,
   canonical/diff pass-through. Unit tests per validator boundary (plan
   §9.5).
2. Core formats + regularization: SRT/VTT parse/serialize with
   round-trip tests (exact ms), tolerance cases, regularization unit and
   property tests (post-conditions D5), fixture transcript with
   realistic whisper-style drift.
3. Render burn-in: composite path, position/box/shadow styling, cache-key
   extension (D7), new corpus document `caption.json` + golden via
   `cargo xtask golden` in a dedicated commit (plan §14), golden corpus
   for old documents asserted unchanged in the same run.
4. CLI: `caption import|export` (SRT/VTT/ASS), `audio analyze` (+`--json`),
   `disciplined.yaml` D10 fix. Integration tests: import → validate →
   render frame hash comparison; analyze on a generated fixture mix;
   round-trip exactness.
5. Whisper feature + docs: `transcribe` feature, model download+cache,
   `caption transcribe`, local E2E on a generated click-track (evidence
   file), README/skills/quillon SKILL.md/AGENTS.md surface updates, NOTICE
   +rsubs-lib/whisper-rs/ureq.
6. Final verification: the three acceptance commands above, full battery,
   `check_diff`, `arch_gate` (corrected config), `coverage_gate` (floors
   80 global / 60 per file), CI green on the final commit, evidence
   bundle under `download/`.

## 5. Rollback

Every schema change is an optional field, so reverting the model commits
restores the previous format exactly; no migration exists to undo. Burn-in
is a no-op without captions, so the golden corpus and `RENDERER_VERSION`
are untouched — a renderer revert needs no golden refresh. Whisper sits
behind a default-off feature: disabling it never affects the default
binary. The disciplined.yaml change is additive and stricter; reverting it
would only re-blind the gate. If a step's checkpoint fails late, the step
commit is reverted on its own; earlier checkpoints are independent.
