# Design Note: v1.0.0-beta.1 (plan §12 "v1.0 — Stabil", beta cut)

Goal: ship the full v1.0 scope as a beta — stable API surface,
published benchmarks with an in-repo harness, a template gallery, a
checksummed 5-platform binary release with installer, and a docs
overhaul that removes everything stale. The plan's 30-day
schema-freeze acceptance cannot be met on day one by definition, so
this is cut as `1.0.0-beta.1`; the freeze clock starts at this tag.

Non-goals: no `crates.io` publish (needs an account we do not have —
`cargo install quillon` stays the documented post-1.0 acceptance), no
new runtime dependencies (NOTICE unchanged), no renderer changes
(golden hashes frozen), no GUI, nothing from plan §15.

Rationale for the two main choices: (1) the release workflow is
hand-written following the cargo-dist 0.34 pattern instead of running
`cargo dist init` because a generated 700-line workflow is hard to
review and the five-target matrix, checksum, and installer steps are
exactly what the generator emits — we keep the reviewed core and lose
nothing; (2) benchmarks use a std-only xtask harness instead of
criterion because research/Q's honesty rules need corpus medians and
p10/p90 of full renders, not microbenchmark statistics, and a
dependency-free harness anyone can rerun with `cargo xtask bench` is
itself part of the published claim.

Dependency direction (who may call whom): `xtask gallery|bench` →
`quillon-core` (load/validate) and the `quillon` binary (render, via
CARGO_BIN or target/debug); `release.yml` → `cargo build --release`
per target; `docs/*` → no code (consumed by Pages); nothing in core
may import cli/render/media/cache/audio (existing workspace layering
unchanged). Block order A → B → C → D → E, each independent to
revert.

## Blocks (each lands as its own checkpoint commit with battery)

### A — Semver surface (API stabil)
Bump `workspace.package.version` 0.4.0 → `1.0.0-beta.1` (all crates
inherit). Audit the public API of `quillon-core` (the publishable
crate): every `pub use` must be intentional; no accidental internal
leaks. Add `docs/STABILITY.md`: what semver means during beta
(additive only, breaking changes get a new `-beta.N`), the document
schema freeze (schema `v` stays 1; `docs/schema.json` is the frozen
contract, exported by `cargo xtask export-schema` and parity-tested),
and the deprecation policy. Verification: schema parity test already
in CI; battery green with the new version; `cargo package -p
quillon-core --list` (metadata dry run, no publish) succeeds.

### B — Template gallery
`templates/` with five showcase documents exercising distinct feature
lanes: title card (text + gradient), lower third (motion + easing),
photo slideshow (image assets + transitions), caption burn-in (SRT
captions over video-style background), social square (shapes +
animated opacity). Each validated; one representative frame rendered
to PNG via the real binary into `docs/gallery-assets/`;
`docs/gallery.md` embeds them with the source JSON linked. Follower
rule for honesty: every gallery image must come from the committed
document, regenerated by a script (`scripts/` in repo via xtask
`gallery`? — no: one-shot script in `xtask gallery` so anyone can
regenerate). Verification: PIL non-blank check per PNG; every
document `quillon validate` exit 0.

### C — Benchmark harness + published numbers (`cargo xtask bench`)
Harness in `xtask` (std only, no new deps) following research/Q's
honesty rules: a corpus of the gallery documents plus the acceptance
fixture; N=5 runs per document; report median + p10/p90 for (a)
validate time, (b) render-only PNG frames/sec (encoder excluded),
(c) end-to-end MP4 wall time; (d) reproducibility — frame hashes
identical across runs (manifest sha256); hardware, threads, encoder
(libx264 software), and ffmpeg version disclosed in the output;
render-only vs end-to-end labeled. Results written to
`docs/benchmarks.md` by the harness itself (not hand-typed).
Verification: run it, read the table, spot-check one timing by hand.

### D — Release pipeline (cargo-dist pattern, manual workflow)
`[workspace.metadata.dist]` config with the five targets verified in
research/L (x86_64/aarch64 linux gnu, x86_64/aarch64 apple darwin,
x86_64 windows msvc). A hand-written `.github/workflows/release.yml`
following the cargo-dist 0.34 pattern (build matrix → tar/zip →
sha256 checksums → GitHub Release on tag `v*`) — hand-written so no
tool install is needed and every step is reviewable. An
`installer.sh` (curl | sh) that detects platform, downloads the right
artifact, and verifies its checksum before install. Cut tag
`v1.0.0-beta.1` and let CI produce the release. Verification: poll
the run; fetch the Release API; confirm 5 platform archives + 1
checksum file + installer attached; installer syntax-checked
(`bash -n`) and its checksum verification path exercised locally by
hand with a downloaded artifact.

### E — Docs overhaul (delete what is stale)
README rewritten for v1.0-beta: what Quillon is, install (installer
+ build from source), the full command surface with one example each,
gallery + benchmarks links, stability policy link, version status
honest. `docs/` becomes: `guide.md` (concepts: document, validation,
render, cache, template data, OTIO, MCP, captions/audio), plus
existing `HARDENING.md`, `gallery.md`, `benchmarks.md`,
`STABILITY.md`. AGENTS.md updated to the new version and xtask
commands. GitHub Pages workflow serving `docs/` (+ README as index
source) — static, no build toolchain. Deletions: the stale "v0.2 in
development" status block and any section describing commands that no
longer exist; `myquillonplan.md` and `research/` stay (they are the
traceable decision record, plan §16.5). Verification: link check
script (every relative link in README/docs resolves to a file);
`scan_disclosure.py` over public docs; every command shown in README
executed at least once.

## Invariants

1. Zero new runtime dependencies; NOTICE untouched; golden hashes
   untouched (no renderer change anywhere).
2. Battery (302+) stays green at every checkpoint; contract table
   still passes (no CLI behavior change except additive).
3. Every published number is machine-generated by the harness, never
   typed by hand.
4. Release artifacts must build on all 5 targets — a failing platform
   blocks the release, it is not dropped from the matrix.

## Rollback

Each block is one commit; the tag can be deleted (no consumers yet)
and the release workflow is additive (CI unchanged). Version bump is
a one-line revert. Docs are additive except README, which is in git
history.
